# Guideline — лендінг CosmoDerm (інструкція для AI-агента)

Ця інструкція — для агента, який переносить макет із Figma в код і змінює сторінку далі.
Прочитай її повністю перед першою зміною. Якщо запит суперечить правилу нижче — спитай, а не вгадуй.

**Джерело дизайну:** Figma `Cosmoderm` → сторінка `34:2`
- Desktop: `CosmoDerm v3 — Desktop 1440` (вузол `77:2`)
- Mobile: `CosmoDerm v3 — Mobile 390` (вузол `77:176`)
- Компоненти: секція `Компоненти — CosmoDerm v3`
- Сценарій основної дії: секція `Сценарій: запис на консультацію` (екрани `88:136 → 88:921`)

---

## 1. Мета сторінки й аудиторія

- **Продукт:** CosmoDerm — AI-щоденник шкіри для пацієнтів косметологічної клініки у Львові. Фото раз на тиждень, план домашнього догляду, питання лікарю між візитами.
- **Аудиторія:** пацієнти в Україні (B2C), переважно жінки 22–45, які проходять курс лікування (акне, розацеа, пігментація) і тривожаться між візитами. Більшість відкриває сторінку з телефона (Instagram → лендінг).
- **Мета сторінки:** одна дія — **записатися на консультацію**. Усе інше (фічі, чат, лікар, FAQ) знімає тривогу й недовіру перед цим кроком.
- **Тон:** спокійний, турботливий, без медичного страху й без «продажного» тиску. Мова — українська, звертання на «ви».

## 2. Дизайн-рішення, які треба зберегти

1. **Візуальна ієрархія:** hero (H1 + телефон із фото) → statement (великий лід) → 4 картки фіч → чат із лікарем → блок лікаря → квіз → FAQ → CTA-банер → футер. Порядок секцій не змінювати.
2. **Багато повітря:** великі відступи між секціями, світлий фон, кольорові акценти лише точкові (теги, іконки, CTA).
3. **Типографіка:** заголовки — Familjen Grotesk 400 з від’ємним трекінгом; текст — Inter; логотип — Cormorant SC. Заголовки не робити жирними: акцент дає розмір, а не вага (виняток — анімація weight wave).
4. **Скруглення:** кнопки й теги — повністю круглі (`--radius-full`), картки — великі м’які радіуси, як у макеті.
5. **Фото людей** — справжні, без «AI-облич». Лікарка Юлія Дідик — лише її реальне фото.
6. **Контент-правила (обов’язкові):**
   - AI **ніколи не ставить діагноз** — «рішення завжди ухвалює лікар».
   - **Жодних вигаданих цифр**: відсотків точності, кількості пацієнтів, відгуків.
   - Тексти беруться з макета або з `CosmoDerm-UX-kontent-lendingu.md`, не вигадуються.

## 3. Стилі, variables і компоненти

Стек: **чистий HTML + CSS + JS** без фреймворків і збірки. Файли: `index.html`, `styles.css`, `script.js` + окремий JS на кожну анімацію.

### Variables (CSS custom properties = Figma variables)
Беремо лише токени з `:root` у `styles.css`. **Не вписувати hex-кольори напряму** в нові правила.

| Група | Токени |
|---|---|
| Текст | `--text-primary` `--text-secondary` `--text-tertiary` `--text-on-dark` `--text-accent` `--text-success` `--text-attention` |
| Поверхні | `--surface-default` `--surface-muted` `--surface-section` `--surface-accent` `--surface-inverse` `--surface-overlay` |
| Акценти | `--accent` / `--accent-soft`, `--success` / `--success-soft`, `--attention` / `--attention-soft` |
| Обводки | `--border-default` `--border-accent` `--border-subtle` `--border-on-image` |
| Відступи | `--page-margin`: 64 → 32 (≤1023) → 20 (≤767); `--content`: 1312px |
| Шрифти | `--font-heading` `--font-body` `--font-logo` |

### Текстові стилі
| Клас | Desktop | Призначення |
|---|---|---|
| `.h1` | 68 / 1.04 | Заголовок hero |
| `.h2` | 52 / 1.04 | Заголовки секцій |
| `.h3` | 44 / 1.08 | Підзаголовки |
| `.lead` | 44 / 1.18 | Statement |
| `.body-18` | 18 / 1.45 | Основний текст |

На мобільному розміри зменшуються в `@media (max-width: 767px)`. Нових розмірів поза шкалою не додавати.

### Компоненти (Figma → CSS-клас)
`Button` → `.btn` + `--primary / --secondary / --inverse` + `--s / --m / --l` · `Tag` → `.tag--*` · `Chip` → `.chip` · `Chat bubble` → `.bubble--patient / --doctor` · `Care task` → `.care-task` · `FAQ item` → `.faq-q` + панель · `Quiz option` → `.quiz-option` · `Input` → `.field__input` · `Choice chip` → `.choice` · `Checkbox` → `.checkbox` · `Icon` → SVG з `assets/icons/`.
Новий елемент спершу збираємо з наявних компонентів. Новий компонент — лише якщо такого немає в Figma.

## 4. Основна дія — «Записатися на консультацію»

Кнопки з `data-booking` (у хедері, на CTA-банері, у sticky-панелі на мобільному) відкривають `<dialog id="booking">`:

1. **Desktop** — модальне вікно по центру; **Mobile** — bottom sheet знизу.
2. Поля: «Ім’я» (обов’язкове), «Телефон» (маска `+380 __ ___ __ __`), «Що турбує?» (Акне / Розацеа / Пігментація / Інше), «Коли зручно прийняти дзвінок?» (Ранок / День / Вечір), чекбокс згоди на обробку даних.
3. «Надіслати заявку» неактивна, доки ім’я, телефон і згода не заповнені. Помилки показуються під полем після blur.
4. Під час надсилання — стан завантаження, потім екран успіху «Заявку надіслано», з підсумком і кнопкою «Готово».
5. Закриття: хрестик, Esc або клік по фону. Фокус повертається на кнопку, яка відкрила форму.
6. Аналітика: `dataLayer` з подіями `booking_open`, `booking_submit`, `booking_success`, `booking_error` (з джерелом кнопки).

**Sticky CTA (лише ≤767px):** з’являється після hero, ховається біля CTA-банера й футера.

## 5. Мобільна поведінка

- Брейкпоінти: 1279 / 1023 / **767** (мобільний макет) / 359 (дуже вузькі телефони).
- Одна колонка; картки фіч ідуть одна під одною; переноси `<br class="d-only">` на мобільному вимикаються.
- **Без горизонтального скролу** на 320–430px. Текст не обрізається (крім чипів з `nowrap` — вони мусять уміщатися).
- Зона натискання для посилань і кнопок — **не менше 44px** заввишки.

## 6. Межі реалізації

**Має працювати по-справжньому:**
- усі якірні посилання й посилання на Instagram;
- форма запису: валідація, маска телефону, стани, успіх, закриття, клавіатура;
- FAQ-акордеон (одночасно відкрите одне питання), квіз;
- адаптивність desktop / tablet / mobile;
- анімації: заповнення statement кольором при скролі, weight wave (H1 і CTA), fan cards, focus mode, before/after;
- `prefers-reduced-motion`: анімації спокійні або вимкнені.

**Можна імітувати:**
- відправку заявки (затримка ~0.9 с без бекенду, лише `dataLayer`);
- чат із лікарем і щотижневі фото — статичні демо, не справжній AI;
- before/after — демо-фото; для продакшну потрібні реальні фото пацієнтки з письмовою згодою.

**Не робити:** бекенд, авторизацію, оплату, збір реальних даних, вигадану статистику.

## 7. Як перевіряти перед здачею

1. Desktop 1440 і mobile 390 + 320: ієрархія, шрифти, кольори, відступи збігаються з Figma.
2. Кожна кнопка `data-booking` відкриває форму; форма проходить увесь сценарій до «Готово».
3. Усі посилання ведуть у свої секції.
4. `document.documentElement.scrollWidth === innerWidth` на мобільному (немає горизонтального скролу).
5. У консолі немає помилок.
6. Коротко опиши, що змінено і що не перевірено.
